# 12/11 — Đo tốc độ và độ chính xác nhiều lần: C++ vs Python trên 5 sequence

## 0. TL;DR

Đo 2 bản × 5 sequence × 3 lần (bỏ 1 lượt warmup), đã khoá xung bằng
`jetson_clocks`. Báo cáo bằng **trung vị**, không phải một lần chạy.

| | C++ | Python | Chênh lệch |
|---|---|---|---|
| backbone | **9.74 ms** | 10.02 ms | −0.28 ms (−2.8%) |
| temporal | **0.97 ms** | 2.79 ms | −1.82 ms (−65.3%, **2.9×**) |
| throughput (model+UI) | **278.9 FPS** | 218.5 FPS | +27.7% (**1.28×**) |
| throughput (+ghi video) | **76.5 FPS** | 69.2 FPS | +10.5% (1.11×) |

**Quyết định khớp 5/5 sequence**: số HARD LOCK, latency, false alarm và
`%verified` giống nhau tuyệt đối, kể cả hai ca thất bại (0 lock) cũng tái hiện y hệt.

Kết luận: C++ nhanh hơn **1.28×** ở tầng model, nhưng phần lớn lợi thế nằm ở
**temporal**, không phải backbone — backbone chỉ nhanh hơn 2.8% vì cả hai cùng
chờ một engine TensorRT ở batch 1.

## 1. Cách đo

Công cụ: `trt_cpp/bench_multi.py`, kết quả thô ở `bench_multi.csv`.

```bash
sudo nvpmodel -m 0 && sudo jetson_clocks
python trt_cpp/bench_multi.py \
    --config configs/config_resnet50_ibn.yaml \
    --backbone v1_backbone.engine --temporal v1_n8_temporal.engine \
    --impl both --nseq 5 --reps 3
```

| Bước | Lý do |
|---|---|
| 5 sequence trải đều theo cỡ bbox (100 px → 166.242 px) | FPS phụ thuộc thành phần video, một sequence không đại diện |
| 3 lần mỗi sequence | lấy trung vị, tránh một lần chạy chậm kéo lệch |
| bỏ lượt chạy đầu | page cache + TensorRT khởi tạo lười |
| bỏ 30 frame đầu mỗi lượt | khử phí khởi động |
| chạy lặp lại để kiểm tính tất định | cùng input + cùng bản phải ra cùng quyết định |

Bốn đại lượng đo được, cùng định nghĩa ở cả hai bản:

| Đại lượng | C++ | Python |
|---|---|---|
| backbone | `backbone (prep+TRT)` | `Avg CNN` + `Avg Preprocess` |
| temporal | `temporal (H2D+TRT)` | `Avg Mamba + Head Time` |
| throughput | `throughput (model+UI)` | `Avg Throughput (model+UI)` |
| +ghi video | `throughput (+ghi video)` | `Avg Throughput (+ghi video)` |

## 2. Tốc độ

Trung vị ± độ lệch chuẩn `[min–max]` trên 15 lượt mỗi bản:

| temporal (ms) | **0.97 ± 0.10** `[0.79–1.13]` | 2.79 ± 0.53 `[2.02–3.56]` |

## 3. Độ chính xác

Hai bản chạy trên cùng video, cùng bbox GT, cùng engine — so quyết định:

| sequence | HARD LOCK | latency (frame) | false alarm | % frame VERIFIED | khớp |
|---|---|---|---|---|---|
| 000270 | 2 / 2 | 218 / 218 | 105 / 105 | 479 / 479 | ✓ |
| 000015 | 1 / 1 | 36 / 36 | 0 / 0 | 218 / 218 | ✓ |
| 000185 | 0 / 0 | – | 0 / 0 | 0 / 0 | ✓ |
| 000418 | 2 / 2 | 37 / 37 | 0 / 0 | 282 / 282 | ✓ |
| 000043 | 0 / 0 | – | 18 / 18 | 0 / 0 | ✓ |

`% frame VERIFIED` là chỉ số gộp: bám được mục tiêu bao nhiêu phần trăm video. Ở
bản C++ đếm trực tiếp cột `state` trong `frames.csv`; ở bản Python dựng lại từ
log (mỗi lần `HARD LOCK` mở một đoạn, đoạn kết thúc ở lần mất kế tiếp). Hai cách
cho cùng kết quả.

Đáng chú ý: hai sequence **000185 và 000043 không lock lần nào**, và bản C++
tái hiện đúng thất bại đó. Đây là bằng chứng mạnh hơn "khớp khi thành công" —
pipeline sai giống nhau ở đúng chỗ khó.

## 4. Đọc kết quả

**1. Backbone gần bằng nhau (2.8%) — đúng như dự đoán.** Cả hai gọi cùng một
engine TensorRT ở batch 1; phần C++ cắt được chỉ là keo dính CPU, mà tiền xử lý
một crop 21×17 chỉ tốn 0.13–0.16 ms. Trần lợi ích ở đây là ~1 ms trên 11 ms.

**2. Temporal nhanh hơn 2.9× là lợi ích thật.** Bản Python cộng overhead
interpreter cho mỗi cửa sổ (4.14 → 2.79 ms sau khi đo lại trên nhiều input), bản
C++ gọi thẳng engine.

**3. Đừng trích FPS làm số đại diện.** FPS thay đổi 200 → 461 giữa các sequence
chỉ vì thành phần video khác nhau: `FPS ≈ tổng_frame / (n_bb × 9.7 ms)`.
000015 chỉ chạy model trên 22% số frame nên "FPS" cao; 000270 chạy 52% nên thấp.
Số trung thực để báo cáo là **9.74 ms mỗi lần gọi backbone**.

**4. Ghi video vẫn là nút cổ chai.** 76.5 FPS khi ghi so với 278.9 FPS khi không
ghi — mã hoá mp4 tốn ~10 ms/frame, gấp đôi model. Mọi cải thiện ở model đều bị
nút này che.

## 5. Hạn chế của phép đo

- **Có trôi nhiệt trong lúc chạy**: backbone C++ 9.11 → 9.77 ms (+7.3%), Python
  9.88 → 10.77 ms (+9.0%) từ đầu đến cuối 40 lượt. Cả hai trôi gần như nhau nên
  **tỉ lệ 1.28× vẫn đáng tin**, nhưng số tuyệt đối hơi cao so với máy nguội.
- **FPS không gồm giải mã video.** Cả hai bản đều đo như vậy nên so được với
  nhau, nhưng không phải FPS thời gian thực của hệ thống.
- **2/5 sequence không lock** (000185, 000043) — vấn đề chất lượng model, không
  phải vấn đề C++.

## 6. Việc tiếp theo

- Đo lại với `--no-video-out` để tách bạch chi phí model khỏi mã hoá video.
- Batch nhiều frame mỗi lần gọi engine: `trtexec` cho thấy batch 12 chỉ ~0.51
  ms/clip so với ~9.7 ms ở batch 1 — đây là đòn tối ưu lớn nhất còn lại.
- INT8 (cần calibration và đo lại ngưỡng đã calibrate).
